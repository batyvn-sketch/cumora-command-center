# 部署对接指南 · Cumora 指挥中心

面向两类人：**要把这个服务跑起来的人** · **要把它接到自己流程里的人**。

> **语言**：**[English](部署对接指南.md)** · **[简体中文](部署对接指南.zh.md)**（页面 UI 支持 `en`/`zh`/`ja`/`ko`/`fr` 五种；文档按同一套语言逐份对应 ⇒ 见「六、变更纪律」第三条）

## 一、前置

| 项 | 要求 |
|---|---|
| Python | 3.9+（只用标准库 · **无第三方依赖**）· 开发环境 3.14 也可 |
| 端口 | 8787 默认（可改） |
| 数据源 | `~/.cumora/daemon.log`（Cumora 的 daemon 日志 · **只读**） |
| 磁盘 | 仓库约 8 MB（`_backup/` 是历史留痕，可删） |

## 二、部署（三种场景）

### A. 本机直接跑（最常见）

```bash
cd /Users/a1234/pi/cumora-command-center
python3 server.py 8787
```

- 首启 Gatekeeper 拦一次 → 点「仍要打开」
- 后台跑：`nohup python3 server.py 8787 > /tmp/cc.log 2>&1 &`
- 验证：`curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8787/api/snapshot` ⇒ 期望 `200`

### B. 换一台机器

```bash
git clone https://github.com/batyvn-sketch/cumora-command-center.git
cd cumora-command-center
python3 server.py 8787
```

**注意**：数据源是**本机**的 `~/.cumora/daemon.log` ⇒ 换机后要么把 daemon 日志接过来（`CC_LOG=/path/to/daemon.log`），要么这台机上就跑着 Cumora ⇒ **服务不会去连远端**（它只读本地文件）。

### C. 常驻（不想它半夜死了）

launchd（macOS）最小例子 → `~/Library/LaunchAgents/com.cumora.cc.plist`：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>com.cumora.cc</string>
  <key>ProgramArguments</key>
  <array><string>/usr/bin/python3</string><string>/Users/a1234/pi/cumora-command-center/server.py</string><string>8787</string></array>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
</dict></plist>
```

```bash
launchctl load ~/Library/LaunchAgents/com.cumora.cc.plist
```

## 三、对接（把数据接进自己流程）

**唯一接口**：`GET http://127.0.0.1:8787/api/snapshot`（JSON · CORS 开放 · 最近 4 小时窗口 + token 全量累计）

| 字段 | 内容 | 注意 |
|---|---|---|
| `tasks` | 任务：`id` / `agent` / `group` / `status`(running/done) / `start` / `end` / `dur_s` / `steps` / `artifacts` / `tools` / `msgs` / `title` | `tasks` 是 **done 的历史**列表（上限 120） |
| `running_tasks` | 正在跑的任务数 | |
| `artifacts` | 产出物：`t`(时间) / `a`(agent) / `g`(群) / `path` | **正在补 `task` 字段**（产出物 ↔ 任务的指针）；无真指针时按「同 agent + 产出物时间落在该任务 [start_ts, end_ts] 内」推定并标 `task_match: "inferred"` |
| `agents` | 7 个：`id` / `name` / `role` / `status` | |
| `groups` | 4 个群 | `GID2SHORT` 映射见 `server.py` |
| `messages` | 消息流（上限 400） | |
| `events` | 事件流（上限 1200） | |
| `comm` | 沟通线（两端 = 两个 agent） | |
| `tokens_g` / `tokens_all` | token 用量：分组 / 分 agent | |
| `generated_at` / `window_h` | 快照生成时刻 / 窗口小时数 | |

**建议的接法**：
- **只读** ⇒ 直接 GET 快照，不要去解析 daemon.log（那是它的工作）
- **轮询** ⇒ 1–2 s 一次足够（页面就是这么做的）
- **别缓存快照** ⇒ 要实时就现读（页面每次刷新都现读）

## 四、页面上「任务—产出物连线」怎么读（新增特性）

- 线 = **产出物 ↔ 任务**（任务再连 agent）
- **每个 agent 保留最近 3 条**（第 4 条起不画）
- 旧线 **30% 透明**，新的那条 100%
- 新产出物一出现 ⇒ 该 agent 的旧线立刻降到 30%，超出 3 条的移除
- **验收**：对每个 agent，连线数 ≤ 3，且每条线两端是「产出物节点 ↔ 任务节点」

## 五、排障

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 打开是空页 / 报错 | 端口没起 | `lsof -nP -iTCP:8787 -sTCP:LISTEN` 看有没有进程；没有就起 |
| 页面像旧版 | 浏览器缓存 | **硬刷**（Cmd+Shift+R） |
| 页面空但接口有数据 | 页面文件不对 | `CC_HTML` 指向正确文件；默认同目录 `Cumora指挥中心.html` |
| 消息数不涨 | 数据源路径不对 | `CC_LOG` 指向真正的 `~/.cumora/daemon.log`；先 `ls -l` 看文件在不在、在不在增长 |
| 图 9/10 的 3D 帧缺失 | 机器无 OpenGL | 正常现象（其余照常） |
| 端口被占 | 老实例还在 | `kill <pid>` 或换 `CC_PORT` |
| 服务半夜死了 | 没有进程守护 | 见上面「C. 常驻」 |

## 六、变更纪律（三条，踩过坑）

1. **落点可追 = 有 commit + 作者是谁**
   共享的 `.git/config` 里 `user.name` 是谁，所有人的提交就都记成谁 ⇒ **每人第一次提交前先 `git config user.name "你的名字"` + `git config user.email "你的邮箱"`**（一次配置永久正确）⇒ 已有历史不改写（改写会把别人的 commit 一起挪动）
2. **唯一源只有一处**
   同一份文件别放两个地方 —— 放了两处，就有一处会过期、而人只会看到过期的那处
3. **文档多语言 = 一次加齐**
   按页面支持的五种语言（`en` / `zh` / `ja` / `ko` / `fr`）逐份对应；**加一种语言就要一次补齐五份**（本指南 + 根 README 各一份）· 逐段对应 · 改一段要改五段 · **当前已落 `en` / `zh` 两份**（页面 UI 的五语言包已全在）
